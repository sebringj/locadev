LocaDev is the loop where the agent does almost everything: gather requirements, clarify them in Slack / Discord / Teams, update Jira and Azure DevOps boards, open PRs with gh, and exercise desk-hosted Azure & AWS–shaped resources — while pre/post hooks refuse decisions and “ready” without citations and receipts. The whole party (AI-driven)

End-to-end automation except the human at the keyboard. Assumes a coding agent plus gh / GitHub, Jira and/or Azure DevOps, and channel bots — local fakes for practice, real APIs for work.

1 Gather

/web-requirements — AI plans, then browses. Signed-in pages: /chrome-debug-profile (CDP). Snapshots become citations; invent later.

2 Clarify in-channel

Open questions go to Slack, Discord, or Teams — same shapes as production. Local fakes expose /ui and /messages so you can see the thread.

3 Ticket the truth

Update Jira and/or Azure DevOps Boards (state, comments, acceptance) from channel + docs — via ./boards/board.sh.

4 Ship with gh

Assumes GitHub CLI is installed and authed: branches, PRs, checks, reviews — agent-driven, human-approved.

5 Local cloud buffet

Summon only the Azure/AWS-shaped bits you need: blobs, bus, SQL, Redis, Functions-style workers, S3, mail, channel fakes — env-only wiring.

6 Grounded “ready”

Pre-hooks demand citations (jira:KEY, ado:#id). Post-hooks demand verify/tests/board/PR receipts.

Jira + Azure DevOps

First-class work boards. Config in .grok/local/boards.json; tokens in env only. Details: boards/README.md.

Jira

Cloud/Server REST: get, comment, transition, JQL search. Cite as jira:PROJ-123. Token: JIRA_API_TOKEN.

ADO

Azure DevOps work items: get, comment, state patch, WIQL search. Cite as ado:#42. PAT: AZURE_DEVOPS_EXT_PAT.

CLI

./boards/board.sh providers|get|comment|transition|search|url — auto-detects key shape; --provider to force.

Pre / post hooks (no hopium)

Big choices and “we’re done” both fail closed without grounding. Protocol lives in hooks/.

⚓ Pre-decision

Before architecture, board rewrites, or committing work: cite docs, channel messages, jira:/ado: keys, or repo paths. ./hooks/pre-decision.sh

✓ Post-ready

Before “ready for review”: verify, tests, Jira/ADO update, gh PR evidence. ./hooks/post-ready.sh

📎 Citations = truth

Empty sources fail the gate. Conflict? Ask the channel again — don’t assume and ship.

Browser skills (what they mean)

Three different jobs — don’t mix them up. Full map: docs/browser-skills.md.

📋 web-requirements

Research the product. AI-first plan, then Playwright snapshots → requirements doc under .grok/local/requirements/. Feeds pre-decision citations.

🔐 chrome-debug-profile

Your logged-in session. Profile work-copy + CDP on :9222. Use when docs/admin UIs need SSO — not for CI e2e.

🧪 playwright

Prove the UI you built. Clean Chromium e2e after implement. Post-ready receipt — not a requirements substitute.

Start the machine

macOS / Linux + Docker Compose v2. Agent toolchain: coding agent, gh, Jira and/or ADO, channel access. README has the deep lore.

1 · Tool up

Agent host + gh auth + boards config (.grok/local/boards.json) + Slack/Discord/Teams (or local profiles).

2 · Summon cloud

make up && make verify — desk-hosted resources on localhost; wire from sandbox.env.example.

3 · Loop with hooks

Gather → clarify → Jira/ADO → code → pre-decision / post-ready → PR. You type; AI drives.

Not magic — just honest

Local cloud is a sidekick, not a free Azure/AWS subscription in a trench coat. Topaz ≠ Entra. PGlite ≠ multi-writer Postgres. AI Search is partial. Hooks force citations so the AI doesn’t paper over those gaps — or invent requirements.
